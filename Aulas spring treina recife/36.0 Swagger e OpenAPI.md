## 💠 O que é o Swagger?

Quando você entrega uma API, quem for consumi-la — um frontend, outro desenvolvedor, um time de testes — precisa saber quais endpoints existem, o que cada um recebe e o que devolve. Sem documentação, isso vira um trabalho manual de ler código ou trocar mensagem.

O **Swagger** (também chamado de **OpenAPI**) resolve isso gerando automaticamente uma **interface visual interativa** com toda a documentação da sua API — direto do código, sem escrever HTML ou PDF manualmente.

Com ele ativo, você acessa:
```
http://localhost:8080/swagger-ui.html
```

E encontra todos os endpoints listados, com exemplos de request, response e a possibilidade de testar direto pelo navegador — como um Insomnia embutido na documentação.

---

## 💠 Dependência no pom.xml

```xml
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.x.x</version>
</dependency>
```

O SpringDoc é a biblioteca que integra o Swagger com o Spring Boot automaticamente.

## 💠 A classe OpenApiConfig

```Java
@Configuration
public class OpenApiConfig {

    @Bean
    public OpenAPI sgpApiOpenAPI() {
        return new OpenAPI()
                .info(new Info()
                        .title("SGP API")
                        .description("API REST para gestão de projetos, tarefas e usuários.")
                        .version("v1")
                        .contact(new Contact()
                                .name("Arthur Cosmo")
                                .email("arthurcosmoservices@gmail.com"))
                        .license(new License()
                                .name("Uso pessoal - Arthur Cosmo")));
    }
}
```

`@Configuration` diz ao Spring que essa classe tem definições de beans. `@Bean` registra o objeto `OpenAPI` no contexto do Spring — o SpringDoc o detecta e usa para montar a página do Swagger com as informações do seu projeto.

## 💠 Anotações nos Controllers

### `@Tag` — agrupa os endpoints por entidade

```Java
@Tag(name = "Usuário", description = "Gerenciamento de usuarios do sistema.")
@RestController
public class UsuarioController { ... }
```

No Swagger UI, os endpoints ficam agrupados por tag — todos os de usuário juntos, todos os de projeto juntos.

### `@Operation` — descreve o endpoint

```Java
@Operation(summary = "Cadastrar usuário", description = "Cadastra um novo usuário no sistema.")
@PostMapping
public ResponseEntity<UsuarioResponseDTO> salvarUsuario(...) { ... }
```

- `summary` — título curto que aparece na listagem
- `description` — explicação mais detalhada

### `@ApiResponse` e `@ApiResponses` — documenta os possíveis retornos

```Java
@ApiResponses({
    @ApiResponse(responseCode = "201", description = "Usuário cadastrado com sucesso."),
    @ApiResponse(responseCode = "400", description = "Dados inválidos."),
    @ApiResponse(responseCode = "409", description = "CPF ou E-mail já cadastrados.")
})
```

Documenta explicitamente cada status HTTP que o endpoint pode retornar e o que ele significa.

## 💠 Anotações nos DTOs

### `@Schema` — descreve campos e dá exemplos

```Java
public record UsuarioRequestDTO(

    @Schema(description = "Nome completo do usuário", example = "João da Silva")
    @NotBlank
    String nome,

    @Schema(description = "CPF do usuário", example = "123.456.789-00")
    @NotBlank @CPF
    String cpf,

    ...
)
```

O `@Schema` faz o Swagger exibir uma descrição e um exemplo para cada campo — quando alguém abrir o Swagger UI e quiser testar, o formulário já vem preenchido com os exemplos que você definiu.

No `ErroPadraoResponseDTO`, a anotação vai na própria classe:

```Java
@Schema(description = "Formato padrão de erro da API.")
public record ErroPadraoResponseDTO(...) {}
```

---

> 💡 **Resumo:** o Swagger gera documentação interativa automaticamente a partir das anotações no código. `@Tag` agrupa, `@Operation` descreve, `@ApiResponse` documenta os retornos, e `@Schema` enriquece os DTOs com exemplos. Tudo acessível em `/swagger-ui.html`.
