## 💠 O que mudou na injeção de dependências

Na versão 2.0, todas as dependências eram injetadas com `@Autowired`:

```Java
@Service
public class UsuarioService {

    @Autowired
    private UsuarioRepository usuarioRepository;

    @Autowired
    private ProjetoRepository projetoRepository;
}
```

Na versão 3.0, `@Autowired` sumiu:

```Java
@RequiredArgsConstructor
@Service
public class UsuarioService {

    private final UsuarioRepository usuarioRepository;
    private final ProjetoRepository projetoRepository;
}
```

O uso dentro dos métodos é idêntico — `usuarioRepository.findById()`, `projetoRepository.existsBy()`. O que mudou foi só a forma de declarar.

---

## 💠 O que o `@RequiredArgsConstructor` faz

É uma anotação do Lombok que gera automaticamente um construtor com todos os campos `final` da classe:

```Java
// O que o Lombok gera por baixo dos panos:
public UsuarioService(UsuarioRepository usuarioRepository, ProjetoRepository projetoRepository) {
    this.usuarioRepository = usuarioRepository;
    this.projetoRepository = projetoRepository;
}
```

O Spring, ao criar o bean `UsuarioService`, vê esse construtor e injeta as instâncias corretas automaticamente — sem precisar do `@Autowired`.

---

## 💠 Por que o `final` é importante

O `final` em Java garante que o campo só pode ser atribuído uma vez — na inicialização. Isso tem duas consequências práticas:

1. **Imutabilidade** — ninguém consegue reatribuir a dependência depois que o objeto foi criado
2. **Detecção em tempo de compilação** — se você esquecer de declarar uma dependência, o compilador avisa. Com `@Autowired`, o erro só aparece em runtime quando a aplicação tentasse usar o campo `null`

---

## 💠 As dependências são injetadas uma vez, não a cada chamada

Um ponto importante: o Spring cria o `UsuarioService` **uma única vez** quando a aplicação sobe, injeta todas as dependências no construtor, e reutiliza essa mesma instância para todas as requisições.

Isso é o padrão **Singleton** — uma instância por bean, compartilhada. Quando você chama `usuarioService.salvarUsuario()` em uma requisição, o `usuarioRepository` já está ali dentro desde o início da aplicação, pronto — não é criado na hora da chamada.

---

## 💠 A partir de agora

Para todos os projetos novos, o padrão é:

```Java
@RequiredArgsConstructor   // ← no lugar de @Autowired
@Service
public class MeuService {
    private final MeuRepository meuRepository;  // ← final, sem @Autowired
}
```

O `@Autowired` ainda funciona, mas é considerado ultrapassado. O Spring Boot oficial recomenda injeção por construtor, e o `@RequiredArgsConstructor` é a forma mais limpa de fazer isso com Lombok.

---

> 💡 **Resumo:** `@RequiredArgsConstructor` gera o construtor com todos os campos `final`. O Spring injeta as dependências via construtor quando cria o bean. As dependências existem desde que a aplicação sobe — não são criadas a cada chamada de método.
