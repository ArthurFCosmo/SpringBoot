## 💠 O que é o SecurityFilterChain

O `SecurityFilterChain` é o coração da configuração do Spring Security. É onde você define as regras da portaria do prédio:

- Quais endpoints são públicos (qualquer um acessa)
- Quais endpoints são protegidos (precisa de token)
- Qual tipo de autenticação usar (stateless, no nosso caso)
- Qual filtro personalizado vai interceptar as requisições

Toda essa configuração fica em uma única classe anotada com `@Configuration`.

---

## 💠 A classe SecurityConfig

Crie a classe no pacote `config`:

```Java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthFilter jwtAuthFilter;

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())
            .sessionManagement(session ->
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/auth/**").permitAll()
                .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
                .anyRequest().authenticated())
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }

    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

---

## 💠 Entendendo cada parte

### `@EnableWebSecurity`
Ativa o Spring Security na aplicação. Sem ela, as configurações do `SecurityFilterChain` não são aplicadas.

### `@EnableMethodSecurity`
Habilita o uso de `@PreAuthorize` nos controllers — que usaremos na página 48.0 para controlar acesso por role. Sem essa anotação, o `@PreAuthorize` é ignorado silenciosamente.

### `.csrf(csrf -> csrf.disable())`
**CSRF** (Cross-Site Request Forgery) é um tipo de ataque que afeta aplicações que usam cookies de sessão. Como a SGP usa JWT no header `Authorization` — e não cookies — esse tipo de ataque não se aplica. Desabilitar é o padrão em APIs REST stateless.

### `.sessionManagement(...STATELESS)`
Instrui o Spring Security a não criar nem usar sessões HTTP. Cada requisição é tratada de forma independente — o servidor não guarda estado entre elas.

### `.authorizeHttpRequests(...)`
Define as regras de acesso:

```Java
.requestMatchers("/auth/**").permitAll()
// ↑ qualquer requisição para /auth/login ou /auth/register passa sem token

.requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
// ↑ a documentação do Swagger também é pública

.anyRequest().authenticated()
// ↑ todo o resto exige um token válido
```

### `.addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)`
Insere nosso filtro JWT **antes** do filtro padrão de autenticação do Spring. Assim, quando uma requisição chega, o nosso filtro extrai e valida o token antes de qualquer outra coisa.

---

## 💠 O `AuthenticationManager`

```Java
@Bean
public AuthenticationManager authenticationManager(
        AuthenticationConfiguration config) throws Exception {
    return config.getAuthenticationManager();
}
```

O `AuthenticationManager` é quem o Spring usa para verificar se um email + senha são válidos. Registrá-lo como `@Bean` permite que o `AuthService` o injete e o use no processo de login — sem ele, não conseguimos autenticar o usuário.

---

## 💠 O `PasswordEncoder`

```Java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

Registra o **BCrypt** como o algoritmo de hash de senhas da aplicação. O Spring Security usa esse bean automaticamente sempre que precisa verificar uma senha. Vamos detalhar o BCrypt na página 44.0.

---

## 💠 A ordem importa

O Spring Security processa as regras do `.authorizeHttpRequests` de cima para baixo, na ordem em que foram declaradas. A primeira regra que casar com a URL vence — as seguintes são ignoradas.

Por isso, as rotas públicas (`/auth/**`) devem sempre vir **antes** do `.anyRequest().authenticated()`. Se você inverter a ordem, o `.anyRequest()` captura tudo primeiro e as rotas específicas nunca são alcançadas.

---

> 💡 **Resumo:** o `SecurityFilterChain` define as regras de segurança da API em um único lugar. CSRF é desabilitado (não se aplica a APIs JWT). A sessão é configurada como STATELESS. Rotas públicas são declaradas com `.permitAll()` antes do `.anyRequest().authenticated()`. O filtro JWT é inserido antes do filtro padrão do Spring. `AuthenticationManager` e `PasswordEncoder` são registrados como beans para uso nos services.
