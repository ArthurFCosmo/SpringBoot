## 💠 O que vamos construir

Os dois únicos endpoints públicos da SGP — aqueles que não exigem token para serem acessados:

- `POST /auth/register` — cadastra um novo usuário do sistema
- `POST /auth/login` — autentica e devolve o token JWT

Todo o resto da API exige autenticação. Esses dois são a porta de entrada.

---

## 💠 Os DTOs de autenticação

Crie no pacote `dto`:

```Java
// Registro — o que o cliente manda
public record RegisterRequestDTO(
    @NotBlank String email,
    @NotBlank String senha,
    @NotNull Role role
) {}

// Login — o que o cliente manda
public record LoginRequestDTO(
    @NotBlank String email,
    @NotBlank String senha
) {}

// Resposta — o que a API devolve após login ou registro bem-sucedido
public record LoginResponseDTO(
    String token,
    String email,
    String role
) {}
```

---

## 💠 O AuthService

Crie no pacote `service`:

```Java
@Service
@RequiredArgsConstructor
public class AuthService {

    private final UsuarioSistemaRepository usuarioSistemaRepository;
    private final PasswordEncoder passwordEncoder;
    private final JwtService jwtService;
    private final AuthenticationManager authenticationManager;

    public LoginResponseDTO registrar(RegisterRequestDTO dto) {

        if (usuarioSistemaRepository.findByEmail(dto.email()).isPresent()) {
            throw new RegraDeNegocioVioladaException(
                "Já existe um usuário cadastrado com o e-mail: " + dto.email()
            );
        }

        UsuarioSistema novoUsuario = new UsuarioSistema(
            null,
            dto.email(),
            passwordEncoder.encode(dto.senha()),  // ← senha hasheada com BCrypt
            dto.role()
        );

        UsuarioSistema usuarioSalvo = usuarioSistemaRepository.save(novoUsuario);

        String token = jwtService.gerarToken(usuarioSalvo);

        return new LoginResponseDTO(token, usuarioSalvo.getEmail(), usuarioSalvo.getRole().name());
    }

    public LoginResponseDTO login(LoginRequestDTO dto) {

        authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(dto.email(), dto.senha())
        );
        // ↑ se o email ou senha estiverem errados, lança AuthenticationException aqui

        UsuarioSistema usuario = usuarioSistemaRepository.findByEmail(dto.email())
            .orElseThrow(() -> new ElementoNaoEncontradoException(
                "Usuário não encontrado com o e-mail: " + dto.email()
            ));

        String token = jwtService.gerarToken(usuario);

        return new LoginResponseDTO(token, usuario.getEmail(), usuario.getRole().name());
    }
}
```

---

## 💠 Como o login funciona por dentro

A linha mais importante do método `login` é:

```Java
authenticationManager.authenticate(
    new UsernamePasswordAuthenticationToken(dto.email(), dto.senha())
);
```

O `AuthenticationManager` — que registramos como bean na `SecurityConfig` — recebe o email e a senha, chama o `UsuarioSistemaService.loadUserByUsername()` para buscar o usuário no banco, e usa o `PasswordEncoder` para verificar se a senha bate com o hash armazenado.

Se qualquer coisa estiver errada — email não existe, senha incorreta — ele lança uma `AuthenticationException` automaticamente. O `GlobalExceptionHandler` vai capturar isso e devolver `401 Unauthorized`.

Se as credenciais estiverem corretas, o método retorna normalmente — e aí buscamos o usuário no banco para gerar o token.

## 💠 O AuthController

Crie no pacote `controller`:

```Java
@RestController
@RequestMapping("/auth")
@RequiredArgsConstructor
@Tag(name = "Autenticação", description = "Endpoints públicos de registro e login.")
public class AuthController {

    private final AuthService authService;

    @PostMapping("/register")
    @Operation(summary = "Registrar usuário", description = "Cadastra um novo usuário do sistema.")
    @ApiResponses({
        @ApiResponse(responseCode = "201", description = "Usuário registrado com sucesso."),
        @ApiResponse(responseCode = "422", description = "E-mail já cadastrado.")
    })
    public ResponseEntity<LoginResponseDTO> registrar(@RequestBody @Valid RegisterRequestDTO dto) {
        return ResponseEntity.status(HttpStatus.CREATED).body(authService.registrar(dto));
    }

    @PostMapping("/login")
    @Operation(summary = "Login", description = "Autentica o usuário e retorna um token JWT.")
    @ApiResponses({
        @ApiResponse(responseCode = "200", description = "Login realizado com sucesso."),
        @ApiResponse(responseCode = "401", description = "Credenciais inválidas.")
    })
    public ResponseEntity<LoginResponseDTO> login(@RequestBody @Valid LoginRequestDTO dto) {
        return ResponseEntity.ok(authService.login(dto));
    }
}
```

## 💠 Adicionando o handler de `AuthenticationException` no GlobalExceptionHandler

Precisamos tratar o caso de credenciais inválidas de forma padronizada. Adicione no `GlobalExceptionHandler`:

```Java
@ExceptionHandler(AuthenticationException.class)
public ResponseEntity<ErroPadraoResponseDTO> tratarAuthenticationException(
        HttpServletRequest request, AuthenticationException exception) {
    return criarExeptionPadrao(
        request,
        HttpStatus.UNAUTHORIZED,
        "Credenciais inválidas. Verifique o e-mail e a senha."
    );
}
```

Agora, ao invés de um erro genérico, o cliente recebe:

```JSON
{
    "timestamp": "2026-08-01T10:30:00",
    "status": 401,
    "error": "Unauthorized",
    "message": "Credenciais inválidas. Verifique o e-mail e a senha.",
    "path": "http://localhost:8080/auth/login"
}
```

## 💠 O que o cliente recebe após login bem-sucedido

```JSON
{
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "email": "arthurcosmo@gmail.com",
    "role": "ADMIN"
}
```

Esse token deve ser copiado e enviado no header de todas as requisições seguintes:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

No Insomnia, isso é feito na aba **Auth → Bearer Token** de cada requisição — ou configurando uma variável de ambiente para reutilizar o token em todas.

---

> 💡 **Resumo:** `AuthService` tem dois métodos — `registrar()` hasheia a senha e salva o usuário, `login()` delega a verificação de credenciais ao `AuthenticationManager` e gera o token se válidas. O `AuthController` expõe os dois endpoints em `/auth/register` e `/auth/login`. O `GlobalExceptionHandler` trata `AuthenticationException` com `401`. O token retornado deve ser enviado no header `Authorization: Bearer` em todas as requisições protegidas.
