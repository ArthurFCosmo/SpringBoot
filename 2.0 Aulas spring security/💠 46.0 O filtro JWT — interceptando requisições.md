## 💠 O que é um filtro no Spring

No Spring, um **filtro** é um componente que intercepta cada requisição HTTP antes que ela chegue ao Controller. É o equivalente ao segurança da portaria — toda requisição passa por ele, e ele decide se deixa passar ou barra na entrada.

O `JwtAuthFilter` é o filtro que vamos criar para interceptar todas as requisições, extrair o token JWT do header `Authorization`, validá-lo, e — se válido — autenticar o usuário no contexto do Spring Security.

---

## 💠 O código do JwtAuthFilter

Crie no pacote `filter`:

```Java
@Component
@RequiredArgsConstructor
public class JwtAuthFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UsuarioSistemaService usuarioSistemaService;

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain) throws ServletException, IOException {

        String authHeader = request.getHeader("Authorization");

        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        String token = authHeader.substring(7);
        String email = jwtService.extrairEmail(token);

        if (email != null && SecurityContextHolder.getContext().getAuthentication() == null) {

            UserDetails userDetails = usuarioSistemaService.loadUserByUsername(email);

            if (jwtService.tokenValido(token, userDetails)) {

                UsernamePasswordAuthenticationToken authToken =
                    new UsernamePasswordAuthenticationToken(
                        userDetails,
                        null,
                        userDetails.getAuthorities()
                    );

                authToken.setDetails(
                    new WebAuthenticationDetailsSource().buildDetails(request)
                );

                SecurityContextHolder.getContext().setAuthentication(authToken);
            }
        }

        filterChain.doFilter(request, response);
    }
}
```

---

## 💠 `OncePerRequestFilter` — por que estender essa classe

O `JwtAuthFilter` estende `OncePerRequestFilter` — uma classe do Spring que garante que o filtro é executado **exatamente uma vez por requisição**, independente de redirecionamentos internos ou encadeamentos de filtros. Sem ela, o filtro poderia ser chamado múltiplas vezes na mesma requisição.

O único método obrigatório de implementar é o `doFilterInternal` — que é onde fica toda a lógica do filtro.

---

## 💠 O fluxo passo a passo

### Passo 1 — Extrair o header

```Java
String authHeader = request.getHeader("Authorization");

if (authHeader == null || !authHeader.startsWith("Bearer ")) {
    filterChain.doFilter(request, response);
    return;
}
```

Toda requisição autenticada deve ter o header:
```
Authorization: Bearer eyJhbGci...
```

Se o header estiver ausente ou não começar com `"Bearer "`, o filtro **passa adiante sem autenticar** — e o Spring Security vai bloquear no passo de autorização se o endpoint for protegido. Endpoints públicos como `/auth/login` passam normalmente aqui.

### Passo 2 — Extrair o token e o email

```Java
String token = authHeader.substring(7);
// ↑ remove o prefixo "Bearer " (7 caracteres) — só o token fica

String email = jwtService.extrairEmail(token);
```

### Passo 3 — Verificar se já existe autenticação

```Java
if (email != null && SecurityContextHolder.getContext().getAuthentication() == null) {
```

O `SecurityContextHolder` é onde o Spring Security guarda a autenticação da requisição atual. Se já existe uma autenticação, não precisamos fazer nada — evita processamento duplo.

### Passo 4 — Carregar o usuário e validar o token

```Java
UserDetails userDetails = usuarioSistemaService.loadUserByUsername(email);

if (jwtService.tokenValido(token, userDetails)) {
```

Busca o usuário no banco pelo email extraído do token, e valida que o token é legítimo e não expirou.

### Passo 5 — Autenticar no contexto do Spring Security

```Java
UsernamePasswordAuthenticationToken authToken =
    new UsernamePasswordAuthenticationToken(
        userDetails,   // ← o usuário autenticado
        null,          // ← credenciais (null pois já validamos)
        userDetails.getAuthorities() // ← roles do usuário
    );

SecurityContextHolder.getContext().setAuthentication(authToken);
```

Cria um objeto de autenticação com o usuário e seus roles, e registra no `SecurityContextHolder`. A partir daqui, o Spring Security sabe quem é o usuário e o que ele pode fazer — e libera a passagem para o Controller.

### Passo 6 — Continuar a cadeia de filtros

```Java
filterChain.doFilter(request, response);
```

Essa linha é obrigatória — ela passa a requisição para o próximo filtro na cadeia (e eventualmente para o Controller). Se você esquecer dessa linha, a requisição trava e o cliente nunca recebe resposta.

---

## 💠 O SecurityContextHolder — o contexto de segurança

O `SecurityContextHolder` é como uma memória temporária da requisição atual. Ele guarda quem está autenticado durante o processamento de uma requisição — e é esvaziado ao final dela.

```
Requisição chega
      │
      ▼
JwtAuthFilter → SecurityContextHolder.setAuthentication(usuario)
      │
      ▼
Controller → pode chamar SecurityContextHolder.getContext().getAuthentication()
      │         para saber quem está logado
      ▼
Resposta sai → SecurityContextHolder é limpo automaticamente
```

Em qualquer ponto do código — service, controller — você pode acessar o usuário autenticado da requisição atual com:

```Java
SecurityContextHolder.getContext().getAuthentication().getName();
// → "arthurcosmo@gmail.com"
```

---

> 💡 **Resumo:** o `JwtAuthFilter` estende `OncePerRequestFilter` e intercepta todas as requisições. Ele extrai o token do header `Authorization: Bearer`, valida com o `JwtService`, carrega o usuário do banco e registra a autenticação no `SecurityContextHolder`. Se o token estiver ausente ou inválido, a requisição segue sem autenticação — e o Spring Security bloqueia se o endpoint for protegido. `filterChain.doFilter()` no final é obrigatório.
