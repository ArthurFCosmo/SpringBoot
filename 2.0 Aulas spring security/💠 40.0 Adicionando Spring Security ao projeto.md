## 💠 O que vamos adicionar

Para implementar autenticação com JWT no SGP, precisamos de duas dependências novas no `pom.xml`:

- **Spring Security** — o módulo de segurança do Spring
- **JJWT** — a biblioteca para gerar e validar tokens JWT

---

## 💠 Adicionando as dependências no pom.xml

Dentro da tag `<dependencies>` do seu `pom.xml`, adicione:

```xml
<!-- Spring Security -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

<!-- JJWT — geração e validação de tokens JWT -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.6</version>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-jackson</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>
</dependency>
```

O JJWT é dividido em três artefatos:

| Artefato | Para que serve |
|---|---|
| `jjwt-api` | As interfaces e classes públicas que você usa no código |
| `jjwt-impl` | A implementação interna — fica em `runtime`, você nunca importa diretamente |
| `jjwt-jackson` | Integração com o Jackson para serializar o JSON dentro do token |

O `scope runtime` significa que `jjwt-impl` e `jjwt-jackson` só são necessários em tempo de execução — o compilador não os enxerga diretamente, mas eles precisam estar no classpath quando a aplicação roda.

---

## 💠 O que acontece ao subir a aplicação pela primeira vez

Assim que você adiciona o `spring-boot-starter-security` e sobe a aplicação, o Spring Security entra em ação **imediatamente** — sem nenhuma configuração adicional.

Você vai notar duas mudanças:

**1. Todos os endpoints ficam bloqueados**

Qualquer requisição no Insomnia vai retornar `401 Unauthorized`. O Spring Security, por padrão, protege tudo.

**2. Uma senha gerada no console**

O Spring gera uma senha aleatória e imprime no console:

```
Using generated security password: 3f8a2d1c-9b4e-4f7a-8c2d-1e5b9a3f7c2d
```

Isso é o comportamento padrão do Spring Security antes de qualquer configuração — ele cria um usuário `user` com essa senha temporária, só para você poder testar. **Ignore essa senha** — vamos substituir tudo isso pela nossa implementação com JWT.

## 💠 Configurando o segredo JWT no application.properties

O JWT é assinado com uma chave secreta — sem ela, qualquer um poderia forjar tokens. Essa chave deve estar no `application.properties` e **nunca deve ser commitada no GitHub** em produção:

```properties
# JWT
api.security.token.secret=sgp-api-secret-key-dev-2026-arthur-cosmo
api.security.token.expiration=86400000
```

- `token.secret` — a chave usada para assinar e validar os tokens. Em produção, deve ser uma string longa e aleatória, armazenada como variável de ambiente.
- `token.expiration` — tempo de expiração em milissegundos. `86400000` = 24 horas.

## 💠 Estrutura de pacotes que vamos criar

Nas próximas páginas, vamos construir os seguintes arquivos. É útil já visualizar onde cada um vai ficar:

```
com.cosmodev.sgp_api_dto_exceptions
├── config
│   └── SecurityConfig.java          ← configura o SecurityFilterChain
├── filter
│   └── JwtAuthFilter.java           ← intercepta e valida o token em cada requisição
├── model
│   └── UsuarioSistema.java          ← entidade de autenticação (quem faz login)
├── enums
│   └── Role.java                    ← ADMIN, GERENTE, COLABORADOR
├── dto
│   ├── LoginRequestDTO.java         ← email + senha
│   └── LoginResponseDTO.java        ← token JWT gerado
├── service
│   └── JwtService.java              ← gera e valida tokens
│   └── AuthService.java             ← lógica de login e registro
└── controller
    └── AuthController.java          ← endpoints /auth/register e /auth/login
```

Cada um desses arquivos vai ser explicado em detalhes nas próximas páginas, construindo a autenticação peça por peça.
