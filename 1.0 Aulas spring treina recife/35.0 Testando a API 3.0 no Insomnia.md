## 💠 O que mudou no Insomnia

Na versão 2.0 os endpoints recebiam a entidade diretamente no body. Na versão 3.0 recebem o **RequestDTO** — sem `id`, com campos obrigatórios definidos. Qualquer campo faltando ou inválido retorna `400` antes de chegar no banco.

## 💠 Usuários

### Cadastrar (POST)
```
POST localhost:8080/usuario
```
```JSON
{
    "nome": "Arthur Cosmo",
    "cpf": "123.456.789-09",
    "email": "arthurcosmo@gmail.com",
    "senha": "1234",
    "dataNascimento": "04/11/2002",
    "status": "ATIVO"
}
```

Resposta `201 Created`:
```JSON
{
    "id": 1,
    "nome": "Arthur Cosmo",
    "cpfMascarado": "123.***.***-**",
    "email": "arthurcosmo@gmail.com",
    "dataNascimento": "04/11/2002",
    "idade": 23,
    "status": "ATIVO"
}
```

> A `senha` não aparece na resposta. O CPF volta mascarado. A `idade` é calculada automaticamente.

---

### Validação falhou (400)

Se você mandar CPF inválido ou nome em branco:
```JSON
{
    "timestamp": "2026-07-08T14:32:05.123",
    "status": 400,
    "error": "Erro na requisição.",
    "message": "cpf: CPF inválido, nome: não deve estar em branco",
    "path": "http://localhost:8080/usuario"
}
```

---

### Buscar por ID (GET)
```
GET localhost:8080/usuario/1
```

Se o id não existir, `404`:
```JSON
{
    "timestamp": "2026-07-08T14:35:10.456",
    "status": 404,
    "error": "Elemento não encontrado.",
    "message": "Não foi encontrado Usuario com o Id solicitado.",
    "path": "http://localhost:8080/usuario/99"
}
```

---

### Tentar deletar usuário com projetos (422)
```
DELETE localhost:8080/usuario/1
```

Se o usuário for responsável por projetos:
```JSON
{
    "timestamp": "2026-07-08T14:40:22.789",
    "status": 422,
    "error": "Elemento improcessável.",
    "message": "O usuário não pôde ser deletado pois existem projetos em que ele é o responsável.",
    "path": "http://localhost:8080/usuario/1"
}
```

## 💠 Projetos

### Cadastrar (POST)
```
POST localhost:8080/projeto
```
```JSON
{
    "nome": "Pelada App",
    "descricao": "Aplicativo de rede social esportiva",
    "dataInicio": "2026-06-01",
    "prioridade": "ALTA",
    "status": "ATIVO",
    "usuarioResponsavelId": 1
}
```

> Note: `usuarioResponsavelId` é um `Long` — só o id do usuário, não o objeto completo.

---

### Listar projetos de um responsável (GET)
```
GET localhost:8080/projeto/responsavel/1
```

Retorna todos os projetos onde o usuário de id 1 é responsável.

---

## 💠 Tarefas

### Cadastrar (POST)
```
POST localhost:8080/tarefa
```
```JSON
{
    "nome": "Implementar tela de login",
    "descricao": "Criar a tela de autenticação do app",
    "dataInicio": "2026-06-10",
    "status": "PENDENTE",
    "usuarioResponsavelId": 1,
    "projetoId": 1
}
```

> `usuarioResponsavelId` pode ser `null` (tarefa sem responsável atribuído). `projetoId` é obrigatório.

## 💠 Tabela completa de endpoints

### Usuários
| Método | URL | O que faz |
|---|---|---|
| `POST` | `/usuario` | Cadastra um usuário |
| `GET` | `/usuario` | Lista todos os usuários |
| `GET` | `/usuario/{id}` | Busca por ID |
| `PUT` | `/usuario/{id}` | Atualiza um usuário |
| `DELETE` | `/usuario/{id}` | Deleta (se não tiver projetos) |

### Projetos
| Método | URL | O que faz |
|---|---|---|
| `POST` | `/projeto` | Cadastra um projeto |
| `GET` | `/projeto` | Lista todos os projetos |
| `GET` | `/projeto/{id}` | Busca por ID |
| `PUT` | `/projeto/{id}` | Atualiza um projeto |
| `DELETE` | `/projeto/{id}` | Deleta (se não tiver tarefas) |
| `GET` | `/projeto/responsavel/{id}` | Lista projetos de um responsável |

### Tarefas
| Método | URL | O que faz |
|---|---|---|
| `POST` | `/tarefa` | Cadastra uma tarefa |
| `GET` | `/tarefa` | Lista todas as tarefas |
| `GET` | `/tarefa/{id}` | Busca por ID |
| `PUT` | `/tarefa/{id}` | Atualiza uma tarefa |
| `DELETE` | `/tarefa/{id}` | Deleta uma tarefa |
