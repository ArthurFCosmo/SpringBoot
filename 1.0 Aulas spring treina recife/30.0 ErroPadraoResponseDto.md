## 💠 Por que padronizar respostas de erro?

Sem um padrão, cada erro da API devolve uma estrutura diferente — às vezes a stacktrace bruta do Java, às vezes uma string, às vezes nada. Isso dificulta o trabalho de quem consome a API (um frontend, outro serviço, um app mobile).

Com o `ErroPadraoResponseDto`, todo erro da API devolve o mesmo formato JSON, independente do que deu errado.

---

## 💠 A classe

```Java
public record ErroPadraoResponseDto(
    LocalDateTime timestamp,
    int status,
    String error,
    String message,
    String path
) {}
```

---

## 💠 O que cada campo significa

| Campo       | Exemplo                                             | Para que serve                     |
| ----------- | --------------------------------------------------- | ---------------------------------- |
| `timestamp` | `2026-07-08T14:32:05.123`                           | Quando exatamente o erro aconteceu |
| `status`    | `404`                                               | O código HTTP do erro              |
| `error`     | `"Elemento não encontrado."`                        | Categoria do erro (curta)          |
| `message`   | `"Não foi encontrado Usuario com o Id solicitado."` | Detalhe descritivo do erro         |
| `path`      | `"http://localhost:8080/usuario/99"`                | Qual endpoint gerou o erro         |

---

## 💠 Por que `LocalDateTime` e não `LocalDate`?

O `LocalDate` armazena apenas a data: `2026-07-08`. O `LocalDateTime` armazena data e hora: `2026-07-08T14:32:05.123`.

Em um log de erros, saber que o erro aconteceu em `2026-07-08` é pouco útil se aconteceram dezenas de erros naquele dia. O `LocalDateTime` permite diferenciar com precisão de milissegundos — essencial para debugging e auditoria.

O formato padrão do `LocalDateTime` inclui data, hora, minutos, segundos e fração de segundos:

```
2026-07-08T14:32:05.123456789
```

---

## 💠 Como fica a resposta para o cliente

Quando um id inexistente é buscado:

```JSON
{
    "timestamp": "2026-07-08T14:32:05.123",
    "status": 404,
    "error": "Elemento não encontrado.",
    "message": "Não foi encontrado Usuario com o Id solicitado.",
    "path": "http://localhost:8080/usuario/99"
}
```

É muito mais útil do que a alternativa sem tratamento:

```JSON
{
    "status": 500,
    "error": "Internal Server Error",
    "trace": "java.lang.NullPointerException at br.com...."
}
```

---

> 💡 **Resumo:** `ErroPadraoResponseDto` é um DTO exclusivo para erros — padroniza o formato JSON de todas as respostas de erro da API. `LocalDateTime` em vez de `LocalDate` para ter precisão de horário no timestamp.
