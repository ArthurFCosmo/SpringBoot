## 💠 O que o ResponseDTO controla

O ResponseDTO é o filtro de saída da API. Tudo que o banco guarda é "crú" — CPF completo, senha, datas em formato ISO. O ResponseDTO decide o que vai para o cliente e em que formato.

---

## 💠 UsuarioResponseDTO

```Java
public record UsuarioResponseDTO(
    Long id,
    String nome,
    String cpfMascarado,
    String email,
    @JsonFormat(pattern = "dd/MM/yyyy")
    LocalDate dataNascimento,
    int idade,
    String status
) {}
```

Decisões de design:
- **`senha` não existe aqui** — entrou no banco mas nunca sai pela API
- **`cpfMascarado`** — o campo tem nome diferente de `cpf` para deixar explícito que é o dado tratado
- **`idade`** — não existe no banco, é calculada na hora
- **`@JsonFormat`** — a data sai no formato brasileiro `dd/MM/yyyy`, não no ISO `yyyy-MM-dd`

## 💠 ProjetoResponseDTO

```Java
public record ProjetoResponseDTO(
    Long id,
    String nome,
    String descricao,
    @JsonFormat(pattern = "dd/MM/yyyy") LocalDate dataInicio,
    @JsonFormat(pattern = "dd/MM/yyyy") LocalDate dataConclusao,
    String prioridade,
    String status,
    Long usuarioResponsavelId,
    String usuarioResponsavelNome,
    List<TarefaResponseDTO> tarefas
) {}
```

Decisões de design:
- Em vez de devolver o objeto `Usuario` inteiro como responsável, devolve apenas `usuarioResponsavelId` e `usuarioResponsavelNome` — o cliente recebe só o que precisa
- `tarefas` é uma lista de `TarefaResponseDTO` — o projeto já vem com suas tarefas embutidas na resposta

## 💠 TarefaResponseDTO

```Java
public record TarefaResponseDTO(
    Long id,
    String nome,
    String descricao,
    @JsonFormat(pattern = "dd/MM/yyyy") LocalDate dataInicio,
    @JsonFormat(pattern = "dd/MM/yyyy") LocalDate dataConclusao,
    String status,
    Long responsavelId,
    String responsavelNome,
    Long projetoId,
    String projetoNome
) {}
```

Decisões de design:
- `responsavelId` e `responsavelNome` podem ser `null` — uma tarefa pode existir sem responsável atribuído
- O projeto aparece só como `id` e `nome`, não o objeto completo

## 💠 `@JsonFormat` — entrada vs saída

Uma dúvida comum: se a data vai formatada (`dd/MM/yyyy`) na resposta, como ela deve ser enviada na requisição?

A resposta: em **formato ISO** (`yyyy-MM-dd`) por padrão, a menos que o RequestDTO também tenha `@JsonFormat`:

```Java
// No RequestDTO — aceita dd/MM/yyyy do cliente
@NotNull @PastOrPresent
@JsonFormat(pattern = "dd/MM/yyyy")
LocalDate dataNascimento,

// No ResponseDTO — devolve dd/MM/yyyy para o cliente
@JsonFormat(pattern = "dd/MM/yyyy")
LocalDate dataNascimento,
```

No projeto atual, o `UsuarioRequestDTO` usa `@JsonFormat` na entrada para aceitar o formato brasileiro. Os ResponseDTOs usam para formatar a saída. São contextos diferentes, mas a mesma anotação.

---

> 💡 **Resumo:** o ResponseDTO decide o que sai, em que nome e em que formato. Dados sensíveis ficam de fora. Dados calculados entram. Relacionamentos viram campos simples (id + nome) em vez de objetos completos.
