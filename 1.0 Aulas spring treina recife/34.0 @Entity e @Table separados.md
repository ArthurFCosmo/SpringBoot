
---

## 💠 Como era antes

```Java
// v2.0
@Entity(name = "TB_USUARIOS")
public class Usuario { ... }
```

## 💠 Como ficou

```Java
// v3.0
@Entity
@Table(name = "TB_USUARIOS")
public class Usuario { ... }
```

---

## 💠 A diferença

As duas anotações fazem coisas diferentes:

| Anotação | O que define |
|---|---|
| `@Entity(name = "...")` | O nome usado para referenciar a entidade em **JPQL** (linguagem de query do JPA) |
| `@Table(name = "...")` | O nome real da **tabela no banco de dados** |

Quando você usa `@Entity(name = "TB_USUARIOS")`, está dizendo ao JPA que essa entidade se chama `TB_USUARIOS` em queries JPQL. Mas o nome da tabela no banco pode ser diferente — se não houver `@Table`, o Hibernate usa o nome da classe (`Usuario`) como nome da tabela por padrão.

---

## 💠 Por que separar é melhor

Usando `@Entity(name = "TB_USUARIOS")` sem `@Table`, você configura o nome JPQL mas **não garante** o nome da tabela no banco. O Hibernate pode usar `TB_USUARIOS` ou `Usuario` dependendo da versão e configuração.

Usando os dois separados:

```Java
@Entity                        // ← entidade com nome padrão (nome da classe)
@Table(name = "TB_USUARIOS")  // ← tabela no banco se chama TB_USUARIOS
```

Fica explícito: o Hibernate sabe exatamente qual tabela usar no banco, sem ambiguidade.

---

> 💡 **Resumo:** `@Entity` registra a classe como entidade JPA. `@Table(name = "...")` define o nome da tabela no banco. Separar os dois é mais explícito e evita comportamentos inesperados. Na versão 3.0 todas as entidades adotaram esse padrão.
