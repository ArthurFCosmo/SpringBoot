
---

## 💠 Como era na versão 2.0

Na versão anterior, todo método de busca seguia esse padrão:

```Java
public DadosUsuario buscarUsuarioPeloId(Long id) {
    Usuario usuario = usuarioRepository.findById(id).orElse(null);

    if (Objects.isNull(usuario)) {
        // TODO: Lançar exceção.
        return null;
    }

    return converterParaDto(usuario);
}
```

Tinha o `TODO` marcando que faltava tratar. O método retornava `null` quando não encontrava, e o Controller precisava verificar esse `null` e decidir o que fazer.

---

## 💠 Como ficou na versão 3.0

```Java
public UsuarioResponseDTO buscarUsuarioPorId(Long id){
    Usuario usuario = usuarioRepository.findById(id).orElseThrow(
        () -> new ElementoNaoEncontradoException("Não foi encontrado Usuario com o Id solicitado.")
    );
    return converterModelParaResponseDTO(usuario);
}
```

O `if (isNull)` sumiu. O `TODO` sumiu. O Controller não precisa mais verificar nada — só chama o service e confia que se chegou até ali, o objeto existe.

---

## 💠 Entendendo o `orElseThrow`

O `findById()` retorna um `Optional<Usuario>` — um container que pode ou não ter um valor dentro. Você já conhecia o `.orElse(null)`, que extraía o valor ou retornava `null`. O `.orElseThrow()` faz o mesmo, mas em vez de retornar `null`, **lança uma exceção** se o valor não existir.

```Java
.orElseThrow(() -> new ElementoNaoEncontradoException("mensagem"))
//            ↑ lambda — uma função anônima que cria e retorna a exceção
//              só é executada se o Optional estiver vazio
```

O `() ->` é um lambda sem parâmetros. O Spring chama essa função apenas quando o `Optional` está vazio — ou seja, quando o id não existe no banco. Se o id existir, o lambda nunca é executado.

---

## 💠 O Controller fica mais limpo

Antes, o Controller precisava verificar null e decidir o status:

```Java
// v2.0 — controller com lógica
DadosUsuario usuario = usuarioService.buscarUsuarioPeloId(id);
if (Objects.isNull(usuario)) {
    return ResponseEntity.notFound().build();
}
return ResponseEntity.ok(usuario);
```

Agora, o Controller só chama o service:

```Java
// v3.0 — controller sem lógica
return ResponseEntity.ok(usuarioService.buscarUsuarioPorId(id));
```

Se o id não existir, a exceção é lançada no service, capturada pelo `GlobalExceptionHandler`, e o `404` é devolvido automaticamente. O Controller não sabe nem que deu errado — e não precisa saber.

---

> 💡 **Resumo:** `orElseThrow` substitui o padrão `orElse(null)` + `if (isNull)`. Ele lança a exceção diretamente, elimina o retorno `null`, e libera o Controller de qualquer lógica de verificação.
