## 💠 Por que validar no RequestDTO?

Quando um cliente manda dados inválidos para a API — um e-mail sem `@`, um CPF com dígitos errados, um campo em branco — esses dados precisam ser rejeitados em algum momento. A questão é: onde?

Existem duas opções:

1. Deixar chegar até o banco de dados, que vai recusar com um erro de constraint
2. **Interceptar já na requisição**, antes de qualquer processamento

A opção 2 é sempre melhor. Ela economiza recursos (não abre conexão com o banco à toa), devolve uma mensagem clara para o cliente, e centraliza a responsabilidade de validação em um único lugar: o RequestDTO.

---

## 💠 As anotações de validação

Essas anotações vêm da dependência **Spring Boot Starter Validation** e são colocadas diretamente nos campos do record:

```Java
public record UsuarioRequestDTO(

    @NotBlank
    String nome,

    @NotBlank @CPF
    String cpf,

    @NotBlank @Email
    String email,

    @NotBlank
    String senha,

    @NotNull @PastOrPresent
    @JsonFormat(pattern = "dd/MM/yyyy")
    LocalDate dataNascimento,

    @NotBlank
    String status

) {}
```

---

## 💠 O que cada anotação faz

| Anotação | Aplica a | O que valida |
|---|---|---|
| `@NotBlank` | `String` | Não pode ser `null`, vazia ou só espaços |
| `@NotNull` | Qualquer tipo | Não pode ser `null` |
| `@Email` | `String` | Deve ser um e-mail válido (tem `@` e domínio) |
| `@CPF` | `String` | Deve ser um CPF matematicamente válido |
| `@PastOrPresent` | `LocalDate` | Data deve ser hoje ou no passado (útil para nascimento) |
| `@FutureOrPresent` | `LocalDate` | Data deve ser hoje ou no futuro (útil para agendamentos) |

> ⚠️ `@NotBlank` só funciona para `String`. Para outros tipos (datas, números, objetos), use `@NotNull`.

---

## 💠 Como ativar as validações no Controller

As anotações no RequestDTO não funcionam sozinhas — elas precisam ser ativadas no controller com `@Valid`:

```Java
@PostMapping
public ResponseEntity<UsuarioResponseDTO> salvarUsuario(
    @RequestBody @Valid UsuarioRequestDTO usuario) {
    return ResponseEntity.status(HttpStatus.CREATED)
        .body(usuarioService.salvarUsuario(usuario));
}
```

O `@Valid` instrui o Spring a inspecionar o objeto recebido e aplicar todas as validações anotadas antes de chamar o service. Se qualquer validação falhar, o Spring lança uma `MethodArgumentNotValidException` — que o `GlobalExceptionHandler` vai capturar e devolver como `400 Bad Request`.

> ⚠️ O `@Valid` vem do pacote `jakarta.validation`, não do Lombok.

---

> 💡 **Resumo:** as anotações de validação ficam no RequestDTO e definem as regras de entrada. O `@Valid` no controller as ativa. Se os dados não passarem, o Spring rejeita a requisição antes mesmo de chegar no service.
