## Telefone

Aplicando a mesma lógica que você já usou nos outros campos — `@NotBlank` pra obrigatoriedade, e pra validar o **formato**, o caminho mais direto é `@Pattern` com uma regex de telefone brasileiro:

```java
@NotBlank(message = "Telefone é obrigatório.")
@Pattern(
    regexp = "^\\(?\\d{2}\\)?[\\s-]?\\d{4,5}-?\\d{4}$",
    message = "Telefone inválido. Use o formato (XX) XXXXX-XXXX."
)
String telefone,
```

#### O que essa regex aceita

Ela é flexível o suficiente pra cobrir os formatos mais comuns que um usuário digitaria:

- `(81) 99999-9999`
- `81999999999`
- `81 99999-9999`
- `(81)999999999`

Isso cobre celular (9 dígitos) e fixo (8 dígitos), com ou sem parênteses/traço/espaço.

#### Explicando a Regex

Vamos quebrar em pedaços, porque regex é ilegível até você aprender a “ler” cada símbolo isoladamente:

```
^\(?\d{2}\)?[\s-]?\d{4,5}-?\d{4}$
```

### Peça por peça

|Trecho|Significado|
|---|---|
|`^`|Marca o **início** da string. Sem isso, a regex aceitaria telefone “escondido” no meio de um texto maior|
|`\(?`|Um parêntese abre `(` **opcional**. O `\` é necessário porque `(` sozinho tem significado especial em regex (agrupamento) — o `\` diz “não, quero o caractere literal `(`”. O `?` logo depois diz “0 ou 1 ocorrência”, ou seja, opcional|
|`\d{2}`|Exatamente **2 dígitos** (`\d` = qualquer dígito 0-9; `{2}` = repete 2 vezes). Isso captura o DDD, tipo `81`|
|`\)?`|Parêntese que fecha `)`, também opcional, mesma lógica do primeiro|
|`[\s-]?`|Um caractere **opcional**, que pode ser espaço (`\s`) **ou** hífen (`-`). Os colchetes `[...]` significam “um caractere qualquer dessa lista”. Cobre o espaço entre `(81)` e o número, ou um traço|
|`\d{4,5}`|Entre **4 e 5 dígitos** — é o intervalo, porque telefone fixo tem 4 dígitos nessa posição (`9999-9999`) e celular tem 5 (`99999-9999`)|
|`-?`|Um hífen opcional, separando a primeira parte do número da segunda (ex: o traço em `99999-9999`)|
|`\d{4}`|Exatamente **4 dígitos** finais — últimos 4 números do telefone|
|`$`|Marca o **fim** da string. Junto com o `^` do início, garante que a regex valida **a string inteira**, não só um pedacinho dela|

### Testando mentalmente com um exemplo real

Pega `(81) 99999-9999` e “encaixa” cada pedaço:

```
(81) 99999-9999
^          → início
\(?  → (
\d{2} → 81
\)?  → )
[\s-]? → (espaço)
\d{4,5} → 99999
-?   → -
\d{4} → 9999
$    → fim
```

Bate perfeitamente. Agora tenta sem formatação nenhuma, `81999999999`:

```
81999999999
\(?  → (nada, é opcional, ok)
\d{2} → 81
\)?  → (nada, ok)
[\s-]? → (nada, ok)
\d{4,5} → 99999
-?   → (nada, ok)
\d{4} → 9999
```

Também bate — todos os grupos opcionais (`?`) simplesmente “não casam com nada” e a regex segue em frente.

### Símbolos-chave pra você guardar (aparecem em quase toda regex)

- `\d` → dígito (0-9)
- `\s` → espaço em branco
- `{n}` → repete exatamente `n` vezes
- `{n,m}` → repete entre `n` e `m` vezes
- `?` → torna o item anterior opcional (0 ou 1 vez)
- `[...]` → “um caractere qualquer dentre esses”
- `^` e `$` → início e fim da string
- `\` antes de um símbolo especial (`(`, `)`, `.` etc.) → “quero o caractere literal, não o significado especial dele”
