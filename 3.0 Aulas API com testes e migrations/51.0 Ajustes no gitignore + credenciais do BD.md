Nesse projeto foi importante fazer alguns ajustes no gitignore padrão.

### 1. O `.gitignore` padrão

Está funcional para o básico (build, IDE), mas **incompleto pro seu caso** — porque não existe nenhuma linha protegendo arquivos de configuração sensível. Isso é crítico dado que você já está pensando em colocar credenciais no `application.properties`.

Eu adicionaria isso no final do arquivo:

```
### Config sensível ###
application-local.properties
application-secrets.properties
.env
*.env
```

### 2. Sobre usuário/senha do banco no `application.properties`

**Não.** E o motivo não é só “boas práticas” abstratas — é bem concreto: o `application.properties` **vai** (e deve) ir para o Git, porque ele contém configurações estruturais do projeto (nome da aplicação, porta, JPA, Flyway) que qualquer pessoa que clonar o repo precisa ter. Se você colocar a senha ali dentro, ela vai parar no GitHub/GitLab público ou privado — e mesmo em repositório privado, uma vez commitada, ela fica no **histórico do Git para sempre**, mesmo que você delete depois (precisaria reescrever o histórico com `git filter-repo` ou similar, o que é bem mais dor de cabeça que prevenir).

### O jeito certo: variáveis de ambiente

No `application.properties`, você referencia variáveis, não valores fixos:

properties

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/${DB_NAME}
spring.datasource.username=${DB_USER}
spring.datasource.password=${DB_PASSWORD}
```

E aí você tem duas formas comuns de fornecer esses valores:

**Opção A — Variáveis de ambiente do SO** (mais “correto” para produção)  
Você exporta no terminal ou configura na IDE:

bash

```bash
export DB_USER=root
export DB_PASSWORD=minhasenha
```

**Opção B — Arquivo `.env` ou `application-local.properties`** (mais prático em dev)  
Você cria um arquivo separado, **fora do controle do Git**, só com os valores reais:

properties

```properties
# application-local.properties (NÃO vai pro Git)
DB_USER=root
DB_PASSWORD=minhasenha
```

E ativa esse profile localmente. Isso é o que a linha que te sugeri no `.gitignore` protege.

### Prática recomendada pro seu caso

Como você está começando o projeto agora, eu sugeriria:

1. `application.properties` → configs genéricas + placeholders `${VAR}`, vai pro Git normalmente
2. `application-local.properties` → suas credenciais reais, **nunca vai pro Git** (já protegido pelo gitignore acima)
3. Quando for rodar, ativa o profile local: `--spring.profiles.active=local`


### Ativando na application.properties

No arquivo `application.properties` foi necessário adicionar a seguinte linha para reconhecer as credenciais:

> `spring.profiles.active=local`
